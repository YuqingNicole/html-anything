# Visual Templates for HTML Explainers

在生成 HTML 前，先选择一个主视觉模板。一个页面默认只用 **一个主模板**；需要补充时最多加一个次模板，避免成为信息拼盘。

## 1. 因果循环 / Feedback Loop

**适用**：宏观经济、平台飞轮、债务、供需、增长—风险之间的自我强化或自我修正。

```text
触发条件 → 中间变量 → 结果
    ↑                    ↓
    └────── 反馈机制 ────┘
```

**HTML 视觉做法**：环状 SVG（带箭头）或四节点圆环；每条边只写一个动词，例如“抬高”“收紧”“挤压”。

**示例**：美债发债 → 收益率 → 全社会融资成本 → 财政利息支出 → 更高发债需求。

**避免**：把所有变量都放进环中。保留 4–5 个核心节点，其余放在边注或分支中。

## 2. 三路传导 / Transmission Branches

**适用**：一个核心变量影响多个群体或市场。

```text
                核心变量
           ↙       ↓       ↘
       家庭企业   金融市场   海外资金
```

**HTML 视觉做法**：中心节点 + 三个等权分支；使用不同但克制的颜色标记分支。每个分支包含“机制 → 可观测指标”。

**示例**：美债收益率 → 房贷与企业债 / 股票估值与银行抵押品 / 美元与海外买盘。

## 3. 输入—转换—输出 / Pipeline

**适用**：API、数据流、AI 工作流、供应链、产品功能。

```text
输入 → 处理 / 规则 → 输出
```

**HTML 视觉做法**：横向三至五站；每站只包含名词和一句极短说明。适合首屏 30 秒理解。

**示例**：用户请求 → API 网关 → 服务处理 → 返回结果。

## 4. 层级剖面 / Layer Cake

**适用**：技术栈、资本结构、AI 供应链、组织结构。

```text
应用层
服务层
基础设施层
底层资源
```

**HTML 视觉做法**：纵向堆栈，各层可展开；强调依赖方向与价值捕获方向不同。

**示例**：AI 应用 → 模型 → 云与芯片 → 电力与数据中心。

## 5. 决策树 / If–Then Map

**适用**：判断框架、风险情景、投资研究、排错。

```text
问题
 ├─ 若 A：看 X
 └─ 若 B：看 Y
```

**HTML 视觉做法**：两到三层决策树，末端应是行动或观察指标，不是抽象结论。

**示例**：收益率上升：若因增长预期 → 风险资产未必受损；若因期限溢价/供给压力 → 关注估值与财政压力。

## 6. 时间轴 / Before–Now–Next

**适用**：政策演变、产品路线图、周期变化、历史解释。

```text
过去的条件 → 当前转折 → 下一步要观察什么
```

**HTML 视觉做法**：三段式时间线；“现在”节点加高亮，未来只写待验证条件，不伪装成预测。

## 7. 权衡天平 / Trade-off Scale

**适用**：政策两难、产品取舍、商业模式张力。

```text
目标 A  ←→  约束 / 代价  ←→  目标 B
```

**HTML 视觉做法**：双侧卡片 + 中央摩擦节点；清晰写出“不能同时最大化什么”。

**示例**：高利率吸引买家 ↔ 高利率抬升美国财政付息成本。

## 模板选择规则

- 解释“为什么会自己越转越快/越脆弱” → 因果循环。
- 解释“会影响谁、通过什么影响” → 三路传导。
- 解释“系统如何运行” → Pipeline。
- 解释“由哪些层组成” → Layer Cake。
- 解释“应该如何判断” → 决策树。
- 解释“从哪里来、到哪里去” → 时间轴。
- 解释“为什么无法两全” → 权衡天平。

## 视觉验收

- 首屏仅有一个主 mental model。
- 节点文字控制在 8–18 个汉字；边上的动词控制在 2–4 个字。
- 颜色是结构编码，不是装饰；每种颜色有固定意义。
- 不确定性必须视觉标注（虚线、浅色、`待验证` 标签）。
- 所有关系在移动端必须可以按顺序阅读，不依赖 hover。
